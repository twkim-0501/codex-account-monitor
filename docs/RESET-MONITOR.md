# 리셋 모니터 통합 기획과 구현

기존 계정 사용량 모니터 안에서 정기 리셋·초기화권·앞으로의 특별 리셋 신호를 확인합니다. 과거 공지 목록을 쌓는 기능은 만들지 않습니다. 모델 작업을 실행하거나 초기화권을 자동으로 소비하지 않습니다.

## 화면과 알림

| 위치 | 표시하는 내용 | 기준 |
| --- | --- | --- |
| 기존 계정 행 | 잔여 한도, 다음 정기 리셋, 초기화권 보유 개수 | Codex 서버 응답 |
| 계정 상세 | 각 초기화권의 만료일, 지급 시각은 도움말로 표시 | 실제 개별 상세가 있을 때만 표시 |
| 다음 특별 리셋 | 24시간·48시간 확률 게이지, 짧은 상태, 예상 시각 | 커뮤니티 확률과 앱의 게시물 판단을 구분 |
| 근거 보기 | 확률 계산 방식, 핵심 근거 최대 3개, 선택적 원문 링크 | 긴 원문 대신 짧은 한국어 요약 |
| 알림 | 새 미래 신호, 계정 한도 회복·시각 변경·초기화권 증가, 만료 임박 | 같은 사건을 다시 알리지 않음 |

계정의 보유 개수는 `rateLimitResetCredits.availableCount`가 기준입니다. 상세 목록은 일부만 제공될 수 있습니다. `credits: null`이면 개별 만료일을 알 수 없고, 빈 배열이면 상세 조회 결과가 비어 있습니다. 기본 유효기간을 가정하지 않습니다. 초기화권을 다른 앱에서 사용하면 다음 계정 조회 때 보유 개수와 정기 리셋 시각이 갱신됩니다.

## 수집 경로

1. [Codex Resets 공개 API](https://codex-resets.com/api/docs)의 현재 상태만 읽습니다. 완료 사건의 최신 경계, 현재 예고와 관찰 중인 신호를 받습니다. 과거 목록 API는 호출하지 않습니다.
2. [CodexReset](https://codexreset.org/) 공개 페이지에 포함된 게시물과 답글의 앞선 글을 읽습니다. 페이지의 JavaScript를 실행하지 않고 데이터 객체만 해석합니다. 현재 스냅샷의 24시간·48시간 확률을 별도로 읽어 출처가 있는 ‘커뮤니티 확률 · 실험적 추정’으로 표시합니다. 사이트의 게시물 분류나 확률로 앱의 판단 상태를 바꾸지 않습니다.
3. 최근 리셋 후보와 `Vote` 답글을 최대 6개 골라 X의 공개 임베드 카드에서 작성자·투표 선택지·종료 시각·앞선 글을 확인합니다. 현재 사용한 경로는 공식 X API가 아니며 형태가 바뀌거나 막힐 수 있습니다.

10분마다 확인하며 전체 조회는 50초 안에 끝내도록 제한합니다. 수집 실패·지연·형식 변경은 화면에 표시합니다. 일부 수집 경로만 실패하면 유효한 기존 신호를 유지하되 새 완료 근거가 있으면 관련 일회성 신호를 내립니다. 계정 식별자·로그인 토큰·이메일은 공개 수집 서버에 보내지 않습니다.

## 판단 기준

1.4.2부터 기본 화면에는 두 확률 게이지, 짧은 판단 상태, 예상 시각만 표시합니다. ‘근거 보기’를 펼치면 확률 계산 방식과 핵심 근거 최대 3개를 짧게 설명하며, 원문 링크는 추가 확인을 위한 선택 사항입니다. 공지 목록과 긴 원문은 기본 화면에 나열하지 않습니다.

확률은 앱에서 학습하거나 검증한 모델의 결과가 아닙니다. 공개 사이트의 현재 추정치를 출처와 함께 표시합니다. 과거 리셋 간격만 반영한 `empirical-baseline`이면 새로운 예고가 반영된 수치가 아님을 설명합니다. 숫자가 0~100 범위를 벗어나거나 24시간 확률이 48시간보다 크면 표시하지 않습니다. 원본의 갱신이 6시간보다 오래됐거나 앱의 조회가 20분보다 오래됐을 때도 ‘—’로 바꿉니다. 수집 실패·형식 변경 시 이전 숫자를 새 추정처럼 유지하지 않습니다.

예측은 다음 순서로 판단합니다.

1. 직접 실행 예고가 있으면 그 시각이나 기간을 우선 표시합니다. 투표 결과로 실행 예고를 뒤집지 않습니다. 초기화권 지급과 사용 한도 리셋은 구분합니다.
2. 진행 중인 일일 조건부 약속이나 투표 관련 약속이 있고, 리셋 선택지가 과반이며, 종료 시각까지 확인되면 단기 리셋 쪽으로 기운 전망을 표시합니다. 일일 약속에 맞춰 **투표 종료 뒤 24시간**을 추정 관찰 범위로 사용합니다. 이 범위는 검증된 실행 시간 예측이나 OpenAI의 약속이 아닙니다.
3. 투표가 반대 방향이면 단기 근거가 약하다고 표시합니다. 득표 수·종료 시각·관련 약속이 부족하면 강한 전망을 만들지 않습니다. 관찰 범위가 지난 뒤에는 같은 투표의 예상 시각을 계속 앞으로 미루지 않습니다.
4. 조건부 약속만 있으면 시각을 추정할 수 없다고 표시하고, 무엇이 추가돼야 전망이 바뀌는지 설명합니다.

`근거 강도`는 직접 예고인지, 서로 연결된 단서가 있는지에 대한 표시입니다. 실제 발생 확률이나 예측 정확도가 아닙니다. 득표 비율은 투표 결과로만 표시하며 리셋 발생 확률로 바꾸지 않습니다. 아직 과거 사례로 정확도를 검증한 확률 모델은 없습니다.

최근 완료 공지와 개선 출시 글은 현재 전망의 맥락으로만 최대 36시간 유지합니다. 완료된 과거 투표를 다음 리셋의 근거로 재사용하지 않습니다. 개선 출시가 있었다는 사실만으로 사용자 평가가 끝났거나 리셋이 취소됐다고 단정하지 않습니다. 수집 누락과 오래된 값은 예측 카드에 바로 표시합니다.

현재 버전은 맥락을 함께 사용하는 규칙 기반 판단입니다. 자유로운 문장을 모두 이해하는 모델은 아니므로 누락 가능성을 명시하고 원문으로 검토할 수 있게 했습니다.

| 결과 | 필요한 근거 | 예시 |
| --- | --- | --- |
| 확정 예고 | Tibo가 미래 실행 의사를 직접 밝힘 | “We will reset … tomorrow” |
| 조건부 약속 | Tibo가 실행 조건이나 개선/리셋 중 하나를 약속함 | “each day … improvement … or … full reset” |
| 힌트 · 미확정 | 투표 선택지의 리셋, 진행 중인 약속에 연결된 Vote, 미래 동작을 암시하는 답글·인용 | “Vote” + “needs a reset” 선택지 |
| 표시하지 않음 | 비밀번호 리셋, 일반 사용자의 요청, 근거가 없는 단독 Vote/Yes, 부정문, 완료·만료된 일회성 신호 | “reset your password”, “No reset today” |

투표에서 리셋이 앞서도 실행을 확정하지 않습니다. 투표 선택지가 누락됐더라도 Tibo의 일일 정리 글과 진행 중인 조건부 약속에 연결되면 약한 힌트로 남기고 누락을 설명합니다. 본문에 reset이라는 단어가 없어도 앞선 글과 미래 동작을 시사하는 답글이 연결되면 힌트로 표시할 수 있습니다. 다른 사람이 쓴 예고를 Tibo 본인의 약속으로 바꾸지 않습니다.

완료 근거가 나오면 그보다 앞선 같은 종류의 일회성 예고·힌트를 내립니다. 한도 초기화와 초기화권 지급은 별도로 처리합니다. 지속되는 조건부 약속은 한 번의 리셋이 끝나도 유지합니다. 수집기에서 확인한 전체 리셋과 특정 계정의 실제 반영을 동일시하지 않습니다.

## 시각과 신호 유효기간

계정 시각은 서버의 Unix 초 값을 사용합니다. 공개 예고의 상대 시간은 게시 시각을 기준으로 계산합니다. today/tomorrow는 게시자의 미국 태평양 날짜를 기준으로 해석합니다. 시간대가 빠지면 정확한 시각을 만들지 않습니다. PT는 해당 날짜의 일광절약시간을 적용하며, 여름에 PST라고 쓴 예고는 UTC-8 기준과 PT 해석의 1시간 차이를 표시합니다. 공개 소식과 초기화권 만료일에는 KST를 명시합니다.

표시를 영구히 유지하지 않기 위해 힌트는 48시간, 시각 없는 일회성 약속은 7일, 구체적 예고는 예정 시각 이후 24시간까지 확인 대기 상태로 둡니다. 이는 **화면에서 신호를 정리하는 기준**이며 OpenAI가 약속한 리셋 시각이 아닙니다. 명시된 N일 조건부 약속은 N일에 날짜 경계 여유 1일을 더해 유지합니다. 예정 시각이 지났다는 이유만으로 완료 처리하지 않습니다.

## 알림과 저장

알림은 새 예고·조건부 약속·힌트, 서버에서 관찰한 한도 회복·정기 시각 변경·초기화권 증가, 초기화권 만료 3일/24시간 이내를 대상으로 합니다. 첫 조회나 계정 변경은 한도 회복 알림을 만들지 않습니다. 한도 감소가 역전됐다는 관찰만 알리고, 원인을 전체 리셋으로 단정하지 않습니다. 조회가 끊긴 계정의 오래된 값으로 만료 알림을 보내지 않습니다.

`%LOCALAPPDATA%\CodexAccountMonitor\reset-state.json`에는 현재 유효한 신호, 그 신호의 앞선 글·투표 상세, 최근 판단 맥락, 종류별 마지막 완료 경계, 중복 알림 방지용 해시를 저장합니다. 게시물 전체 목록은 저장하지 않습니다. 알림 해시는 최대 256개·33일로 제한하며 원문이나 이메일을 담지 않습니다. 알림은 순서대로 표시하며 Windows의 알림 설정을 따릅니다. 앱이 꺼져 있으면 수집·알림도 멈춥니다.

## 검증 방법

저장소 루트에서 Windows PowerShell로 다음 명령을 실행합니다. 첫 명령은 네트워크 없이 판단·파싱·알림 조건과 기존 RPC 동작을 검사합니다. 두 번째는 현재 공개 소식을 실제 조회하며, 세 번째는 로컬 계정의 실제 초기화권 상세를 확인합니다. 계정 조회는 모델 작업을 시작하지 않습니다.

```powershell
dotnet run --project tests/CodexAccountMonitor.Tests -c Release
dotnet run --project tests/CodexAccountMonitor.Tests -c Release -- --feed-live
dotnet run --project tests/CodexAccountMonitor.Tests -c Release -- --live local
```

정상 결과는 모든 검사 PASS와 종료 코드 0입니다. 실시간 공개 수집에서 부분 누락이 있으면 `PartialCoverage`와 `Note`를 함께 확인합니다. UI는 `--layout-check`로 계정/리셋 상세를 펼치고 새로고침·너비 변경·화면 높이 제한을 검사합니다.

2026-10-07 Windows 개발 PC에서 1.4.2의 판단·예측·파싱·알림 및 기존 RPC 검사 **93개**, 3개/8개 가상 계정의 화면 검사 **각 19개**, 실제 계정 3개의 위젯·연결 검사 **18개**를 통과했습니다. 기본 카드에 두 확률이 보이고 긴 설명은 숨겨지는지, 펼치면 짧은 근거와 링크가 보이는지, 오래된 확률이 사라지는지, 투표 역전이 판단 상태에 반영되는지 확인합니다. 실시간 공개 조회와 실제 화면에서도 당시 원본 확률 30%/52%와 최신 리셋 경계를 확인했습니다. 알림 표시 여부는 Windows 알림 설정에 따라 달라집니다.

공식 계정 필드의 정의는 [Codex app-server 문서](https://learn.chatgpt.com/docs/app-server)에 따릅니다. 앞으로 수집 신뢰도를 높이려면 공식 X API 어댑터를 추가할 수 있습니다. 현재 구현에 유료 X API나 LLM API 키는 필요하지 않습니다.
